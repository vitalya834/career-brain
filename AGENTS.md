# Career Brain

For discovery, run `python -X utf8 career.py discover "IT Support | Anwendungsbetreuung" "Köln | Bonn"` or choose a preset from sources.json. Read source errors and search coverage from the JSON. Use its saved_card, similar_saved_role and known_company fields as review signals. Open the original posting and verify date, location, language and hard requirements. Check EURES and other manual links when widening beyond the configured employers, and keep search results separate from applications.

Read Vault/Профиль.md and sources.json. Read the configured history notes (sources.json → history, history_files) before suggesting or saving leads. Search employer aliases, title, location and vacancy ID across configured notes and local cards. A match is a prompt to review, since the same employer can have a different vacancy. Check the employer's actual posting, note the date and separate open positions, unsolicited inquiries and closed listings. Do not infer application status from a generated CV. Use explicit evidence for sent applications, inquiries, rejections and interviews. Save new leads as Markdown cards, and use career.py dashboard to refresh the view. For a CV draft, use career.py brief and check the current source profile and vacancy requirements. Keep the user's own notes authoritative when snapshots or imported statuses conflict. Read only the relevant work notes. Keep files local. Send applications or contact employers only when the user explicitly requests the action.

Before a CV goes out, run `career.py ats ID` and fix every fact-guard warning. Never add skills, certificates or language levels the candidate does not have.
